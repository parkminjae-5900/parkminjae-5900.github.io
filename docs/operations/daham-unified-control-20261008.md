## 단일 업무 원장
각 작업은 task_id, project_id, owner_channel, assignee, source_url, action, status, updated_at, evidence, checkpoint, next_action, dependency, last_run_id, content_hash로 기록.
업무 ID와 증거 없는 완료 보고 금지. 외부 도구의 실행 여부를 추정하지 않음. 고객정보/인증정보는 원장에 기록 금지.

## 중복 방지
1. 동일한 프로젝트+대상 URL+작업 목적+입력 버전으로 dedupe_key 생성.
2. 실행 시작 전에 진행중/완료/실패/차단 상태 확인.
3. 기존 진행 작업이 있으면 중복 실행하지 않고 결과만 참조.
4. 변경되지 않은 데이터는 재검색 대신 이전 검증 결과와 확인시각 사용.
5. 실패시 한 차례 재시도 후 안전한 대체 경로, 권한·승인 우회 금지.
6. 게시·배포는 실제 커밋/PR/배포 상태/웹 검증이 있어야 완료 처리.

## 주기 운영
- 통합 작업 큐: 기존 시간당 순차 실행은 유지하되, 회차마다 모든 분야를 새로 조사하지 않고 미완료/변경 작업에 집중.
- 블로그/카페: 오전 11시 기존 제작 예약 1개만 유지. 오후 2시·7시 중복 예약 중지.
- 부천·인천 SEO 별도 매시간 감시: 중지. 통합 실행과 일일/주간 검색 점검 결과 공유.
- 경쟁사 감시: 변경 시에만 보고.
- 법규·가격: 주 1회 및 공식 데이터 변경 시 검증, 근거 없는 자동 덮어쓰기 금지.
- 작업마다 새 AI 대화·전체 조직 규칙 반복 투입 금지.

## 분산 실행
GitHub Actions와 PC 스케줄러는 정해진 데이터 수집/검증/테스트를 맡고, ChatGPT는 예외판단·문서/디자인 품질평가·검증에 집중한다. 외부 실행기 실제 연결 전에는 작동 중이라 표시하지 않는다. 연결된 도구별 자체 사용량 제한도 따로 관리한다.
