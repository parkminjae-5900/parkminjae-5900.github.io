# 실제 장례 데이터 업로드 워크플로

## 사용방법

앞으로 ChatGPT 대화에 아래 자료를 올리면 이 순서로 처리합니다.

1. 행사사진 원본
2. 장례 영수증 또는 정산 영수증
3. 사용자가 알고 있는 행사 조건이 있으면 함께 사용
   - 장례식장
   - 지역
   - 장례형태
   - 상품
   - 조문객 수
   - 행사 월

사용자가 이미 알려준 정보는 다시 묻지 않습니다.

## 자동 처리 순서

### A. 원본 분석
- 사진을 외관/내부/제단/분향소/접객실/화환/입관/발인/차량/화장장/장지/유골함/서류로 분류
- 영수증에서 실제 금액 항목 추출
- 상품가와 외부비용을 분리
- 합계가 원본 영수증과 맞는지 검산

### B. 공개 금지정보 제거
다음 정보는 공개 데이터에 넣지 않습니다.
- 고인 실명
- 상주/결제자 실명
- 전화번호
- 계좌번호/카드번호
- 주민등록번호/생년월일
- 서명
- 상세 자택주소
- QR/바코드 및 결제식별번호
- 기타 개인 식별 가능 정보

유족/조문객/고인 얼굴은 기본적으로 공개하지 않습니다.
사진 공개에 명시적 허가가 없는 경우, 식별 가능한 사람이 없는 사진만 사용하거나 공개용으로 비식별 처리합니다.

### C. 시설 원본 식별자 검증
공개 사례는 아래 5개 값을 함께 확인합니다.
- facilityName: 사례의 장례식장명과 일치
- address: 공식 주소
- officialBranchName: 공식 지점명
- sourceUrl: HTTPS 공식·공공 출처
- facilityCode: sourceUrl의 정확한 query/path 값

브랜드명이 같아도 주소·공식 지점명·지점코드가 다르면 같은 시설로 합치지 않습니다. 이 값이 없거나 서로 맞지 않으면 공개 집계와 운영 승격에서 제외합니다.

### D. 비용 검증
각 항목은 근거를 표시합니다.
- receipt: 영수증 확인
- user_confirmed: 사용자 확인
- facility_document: 시설 공식자료 확인

추정값은 실제 비용으로 공개하지 않습니다.

### E. 공개 사례 데이터 생성
경로:
data/actual-cases/cases/<case-id>.json

필수 공개 게이트:
- publication.publish = true
- publication.privacy_reviewed = true
- publication.costs_verified = true
- 공개 사진이 있으면 사진별 privacy_checked = true

하나라도 충족하지 않으면 공개 페이지를 생성하지 않습니다.

### F. 자동 생성
GitHub Actions가 다음을 자동 생성합니다.
- actual-case-<case-id>.html
- actual-cases.html
- data/actual-cases/public.json
- sitemap.xml 등록

### G. 검색자산 연결
사례 페이지는 다음으로 연결합니다.
- 해당 장례식장 시설 페이지
- 해당 지역 장례비용 페이지
- 장례비용 계산기
- 가족장/무빈소/후불상조 관련 페이지

## 공개 문구 원칙

항상 "해당 행사 당시 실제 지출 사례"로 표현합니다.
역사적 실제 비용을 현재 장례식장의 고정가격이나 보장가격처럼 표현하지 않습니다.

## 1건의 사례에서 만드는 검색자산

한 건의 원본 데이터로 다음 검색의도를 하나의 canonical 사례페이지가 커버합니다.
- 장례식장명 + 실제 비용
- 장례식장명 + 가족장/무빈소/3일장
- 장례식장명 + 조문객 규모
- 지역 + 실제 장례비
- 지역 + 가족장/무빈소 비용
- 상품 + 실제 총비용

키워드별 복제 doorway 페이지는 만들지 않습니다.

## 사용자에게 보여줄 최종 확인

공개 직전에는 다음만 간단히 보고합니다.
- 공개할 장례식장/지역
- 장례형태/조문객
- 공개할 비용 합계
- 사용할 사진 수
- 비식별 처리 완료 여부

자료가 충분하고 공개 가능성이 명확하면 질문을 최소화하고 진행합니다.
