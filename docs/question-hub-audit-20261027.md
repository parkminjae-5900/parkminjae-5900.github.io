## 결론과 범위
운영 페이지는 HTTP 200이며 배포 실패 증거는 없다. 운영 허브·첫 화면·사이트맵·robots.txt는 검사 시점 GitHub 메인과 바이트 단위로 동일했다. 다만 대표 경력은 첫 화면 24년과 5개 연결 페이지의 23년이 혼재했고, 신규 페이지의 공유 이미지 메타데이터가 저장소 검사 기준을 충족하지 못했다. 이 변경안은 두 문제를 수정한다. 검색 순위·색인·AI 인용 개선을 달성했다고 주장하지 않는다.

검수 기준: 운영 응답, 코드/운영 일치, 내부 연결/이미지, 경력 일관성, 표준주소/구조화 데이터, 검색 관측과 색인 구분, 측정 재현성을 각각 평가했다. 미검증을 정상 또는 실패로 바꾸지 않는다.

- https://support.google.com/webmasters/answer/9012289 : 실제 페이지 테스트와 저장된 색인 정보를 구분하며, 색인됨도 검색 노출을 보장하지 않음.

## 초기 측정 방법과 기록 규칙
- 원본 100문항은 변경하지 않는다. question_set_version은 baseline-100-20261027로 고정하며 번호와 원문을 함께 저장한다.
- 위 20문항을 챗지피티·제미나이·퍼플렉시티의 검색 가능한 모드에서 각각 독립된 새 대화로 3회 실행: 계획 표본 180회. 실제 지원 여부와 화면에 표시되는 모델/모드를 기록하고 미확인 모델명을 추정하지 않는다. 이번 작업에서는 AI 응답 실측을 실행하지 않았으므로 초기 인용률은 미측정이다.
- 한국어, 한국 지역 조건, 같은 질문 원문, 동일한 시간대 범위 및 로그인·개인화 조건을 가능한 한 고정한다. 웹검색 요청 모드와 실제 검색 수행 증거는 구분한다.
- 기존 대화·메모리의 브랜드 정보를 제공하지 않으며, 답변에 다함상조를 넣으라는 추가 지시를 하지 않는다. 플랫폼·반복 순서는 순환하여 시간대 편향을 줄인다.
- 052/055/058/061/064는 브랜드명은 없지만 120·249만원이라는 특정 가격 단서가 있다. 일반 비브랜드 표본과 합치지 않고 별도 가격단서 집단으로 관리한다.
- 답변 원문/화면 또는 검증 가능한 응답 링크, 실제 인용 링크 전체, 경쟁사 언급, 실행 시각(한국시간+시간대), 플랫폼/모델/모드, 실행번호를 저장한다. 검색 결과 링크를 답변의 인용으로 대신 기록하지 않는다.
- 다함상조 언급, 다함 도메인 인용, 신규 허브 정확한 URL 인용, 해당 근거가 주장과 맞는지를 별도 필드로 기록한다. 장준모도 별도 지표로 분리하고 소유관계가 확인된 URL만 집계한다.
- 허브 인용은 경로 funeral-questions.html의 정확한 링크를 기준으로 하며 앵커·추적 인자는 정규화해 중복 제거하되 원본 URL도 보관한다. 검색엔진 캐시나 제3자 요약은 직접 허브 인용으로 세지 않는다.
- 브랜드가 언급되지만 링크가 없는 경우 언급=참, 인용=거짓. 응답 접근 실패·요청 제한·중단은 실패/미측정으로 기록하고 0회 인용으로 넣지 않는다. 정상 응답인데 인용이 없으면 인용=거짓이다.
- 도메인 인용률 = 해당 도메인 인용이 1개 이상인 유효 응답 수 / 유효 응답 수. 허브 인용률·언급률도 각각 같은 방식. 인용 링크 수를 분자로 사용하지 않는다.
- 플랫폼별 n/N과 비율, 질문별 0~3회 성공, 의도별 결과, 실패 건수를 함께 기록한다. 검색 활성 응답만의 비율을 별도로 볼 수 있지만 전체 유효 응답 비율도 보존한다. 3회 반복은 통계적 유의성을 입증하지 않는다.
- 첫 관측을 초기값으로 두고 같은 문항·환경으로 7일·14일·28일 후 비교하는 설계다. 이는 측정 절차 제안이며 예약 실행을 생성한 것은 아니다. 개편 전 데이터가 없으므로 이후 변화만으로 개편의 인과 효과를 단정하지 않는다.
- 원본 CSV는 플랫폼·모델·반복·응답 증거·실행 상태·정확 허브 인용 필드가 없어 그대로는 재현 가능한 비교에 부족하다. companion JSON 템플릿을 1회 실행당 한 레코드로 사용한다. null은 미측정이며 false와 구분한다.
